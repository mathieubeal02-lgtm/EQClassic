# Architecture

## Processes

```
EQ client (Trilogy, via EQW.exe)
   │ UDP (custom EQ protocol: ACK/sequencing/fragments, see LS/Login/Protocol.txt)
   ▼
Login (LS/Login) ── port 5999 (LOGIN_PORT, Common/Include/config.h)
   │ account auth (DES via OpenSSL, LOGINCRYPTO) ─ table login_accounts (LS/Login/loginserver.sql)
   ▼
World (World/) ── TCP 9000 for zones/console + UDP for clients (World/Source/net.cpp)
   │ character select, zone list, guilds, boats, time of day
   ▼
Zone (Zone/) ── one process per zone
     launched as: zone <zone_name> <address> <port> <worldaddress>   (Zone/Source/net.cpp:70)
     e.g. Zone/Boot5zones.bat: `zone . localhost 7996 localhost`
```

Item data is shared between World and Zones through `SharedMemory.dll`
(`SHAREDMEM_NAME "EMuShareMem"`, define `EQC_SHAREDMEMORY`).

All three servers talk to a single MySQL database (`db.ini`). Only the login schema is in the
repo (`LS/Login/loginserver.sql`); the world/zone schema comes from the external
`eqclassic_db` dump (see `docs/BUILD.md`). ~30 tables are referenced from code, e.g.
`spawn2`, `npc_types`, `loottable*`, `lootdrop_entries`, `faction_*`, `npc_faction`,
`tradeskill_recipe*`, `zone_points`, `zone_line_nodes`, `grid_entries`, `quest_globals`,
`player_corpses`, `petitions`, `zone_state_dump`, `forage`, `fishing`, `variables`.

## Zone internals (where the game logic lives)

- `Zone/Source/client_process.cpp` (~6.9k lines) — dispatch of client opcodes (`ProcessOP_*`).
  Input validation raises `EQCException` ("Probably a hacker?").
- `Zone/Source/client.cpp`, `Client_Commands.cpp` — client state, `#` GM commands.
- `Zone/Source/mob.cpp`, `npc.cpp`, `NpcAI.cpp`, `hate_list.cpp`, `attack.cpp` — entities, AI, combat.
- `Zone/Source/spells.cpp`, `Spell*.cpp`, `SpellsHandler.cpp` — spell system; data from
  `spdat.eff` + `spells_en.txt` (copied from the client) + `SpellData.cpp` overrides.
- `Zone/Source/loottables.cpp`, `faction.cpp`, `Tradeskills.cpp`, `forage.cpp`, `Fishing.cpp`.
- `Zone/Source/spawn2.cpp`, `spawngroup.cpp`, `nodes.cpp` — spawns and roaming grids.
- `Zone/Source/Map.cpp`, `watermap.cpp` — `.map` collision / line-of-sight (needed for spawns).
- `Zone/Source/embperl.cpp`, `embparser.cpp`, `questmgr.cpp`, `perl_*.cpp` — embedded Perl 5.12
  quest engine. Quests are loaded from `quests/<zone>/...pl`, `quests/plugins/*.pl`,
  `quests/<zone>/player.pl`. `perl_*.cpp` are generated by `Utils/perlxs/convert`.
- `Zone/cfg/*.cfg` — binary zone headers (101 zones), saved with `#zsave`.

## Common layer

- `Common/Include/eq_packet_structs.h` (~2.2k lines) and `eq_opcodes.h` — wire structures
  and opcodes for the Trilogy client. These are binary layouts: do not reorder fields.
- `Common/Source/EQPacket*.cpp`, `Fragment*.cpp` — reliable-UDP layer.
- `Common/Source/database.cpp` (~5k lines) — all SQL for World/Zone via `RunQuery`.
- `Common/Include/config.h` — game constants (level caps, name lengths, tick time, `db.ini` name).

## State of the code (as of the Phase 0 audit, Sept 2026)

- Build: Windows x86 only, VS2022 (v143). No CI, no tests.
- Dead/duplicated code: an older EQEmu tree lived under `LS/zone` and `LS/common`; the parts
  Login does not need were moved to `legacy/`.
- Security surface: ~330 `RunQuery` calls built with `sprintf`/`MakeAnyLenString` (SQL
  injection on player-controlled strings), ~1.3k `strcpy`/`sprintf`, `memcpy` from raw
  packet buffers, no smart pointers. Login ships the client DES key
  (`LS/Login/eqcrypto_dll_removed.README.txt`).
- ~360 `TODO/FIXME/HACK` markers.
